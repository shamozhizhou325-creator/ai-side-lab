# AI副业实验室自动驾驶协作协议

更新时间：2026-06-11

## 协作目标

让 Codex 承担项目的日常推进工作，Jack 只在关键节点做确认。目标不是承诺收益，而是用持续实验提高赚钱概率：每天有产出、每周有复盘、每月决定继续或换方向。

## 默认工作模式

每天上午 9:30，Codex 主动生成当天工作包：

1. 今日目标
2. 昨日/上次进展
3. 今天可自动完成的事项
4. 需要 Jack 确认的事项
5. 合规风险检查
6. 下一步建议

## 深度工作标准

Jack 希望 Codex 把当前 Codex 账号的大部分有效用量投入到 AI副业实验室。  
因此，自动驾驶不应停留在提醒、简单文案、简单作图，而要围绕赚钱概率做持续研究、实践、总结和迭代。

### 每日最低有效产出

除非 Jack 明确暂停，Codex 每天至少应完成以下四类中的两类：

1. **调研增量**：研究一个近期平台规则、成功案例、竞品账号、工具或变现路径，并沉淀成项目可用结论。
2. **实践增量**：产出一份可直接发布、可交付、可销售或可测试的资产。
3. **迭代增量**：基于已有数据改进标题、封面、正文、网站、模板、报价或用户路径。
4. **复盘增量**：更新数据记录，给出继续、调整、暂停或换方向的判断。

### 无效工作定义

以下工作不算有效产出：

- 只写泛泛计划，不落地文件或素材。
- 只做没有使用场景的图片。
- 只复述旧结论。
- 只追热点，不判断是否适合 Jack。
- 只做看起来忙但不能推进发布、获客、成交或复盘的动作。

### 每日工作优先级

1. 第一优先：已发布内容的数据复盘和下一篇迭代。
2. 第二优先：能带来真实反馈的公开内容。
3. 第三优先：能低成本变现的模板、服务包、报价单。
4. 第四优先：网站、飞书、GitHub 等基础设施优化。
5. 第五优先：长期方向研究。

### 跨平台情报雷达

Codex 需要定期观察小红书、抖音、YouTube、X/Twitter、GitHub 等平台，寻找可融入项目的成功经验、工具、内容结构和新项目机会。

情报不是为了追热点，而是为了回答：

- 有没有更接近赚钱的细分用户？
- 有没有更低成本的交付方式？
- 有没有可借鉴的标题、封面、脚本和服务包结构？
- 有没有 90 分以上的新项目值得 Jack 单独启动？

每次情报整理必须沉淀到项目文件，优先形成：

- 可执行结论
- 候选项目评分
- 内容选题
- 模板或服务包
- 合规风险提醒

当前雷达文件：`ops/cross-platform-intelligence-radar.md`

### 时间与资源原则

Codex 不能承诺像人类一样连续在线工作四小时，但每次被唤醒或用户授权推进时，应按“深度工作块”标准执行，而不是浅层响应。  
如果当天没有足够信息或权限继续推进，Codex 必须明确告诉 Jack 卡点是什么，以及 Jack 只需做哪一个最小动作。

### 每日汇报格式

每日汇报必须包含：

- 今天真正推进了什么。
- 新增了哪些可复用资产。
- 发现了什么风险或机会。
- 下一步需要 Jack 做什么。
- 哪些事情暂时不值得做。

## Codex 可以自动完成

- 小红书标题、正文、话题、封面方案
- 网站文案与工具优化
- 模板包、清单、报价单、客户问卷
- 飞书/Excel 运营表更新
- GitHub 提交、Vercel 部署检查
- 内容敏感词与合规自查
- 市场调研、竞品拆解、案例复盘
- 每日工作包和每周复盘
- 给 Gemini 等外部模型分配调研、竞品扫描、反对意见审查任务，并由 Codex 负责筛选落地

## 必须 Jack 确认

- 公开发布到小红书、抖音、朋友圈等账号
- 使用真实头像、姓名、手机号、微信号、收款码
- 涉及实名、人脸、短信、邮箱验证码
- 涉及付款、投流、购买工具、开会员
- 涉及客户报价、收款、退款、承诺交付
- 涉及医疗、金融、投资、法律、功效类敏感内容
- 平台出现违规、限流、申诉、账号异常提示

## 国内平台发布前网络检查

小红书、飞书、微信、抖音等国内平台发布前，必须先检查发布通道。

### 必查项

1. 当前终端或发布环境不应使用不确定的海外代理出口。
2. 工具站链接必须用直连方式测试可访问，例如：

   `curl -I --max-time 8 --noproxy '*' https://ai-side-lab-zeta.vercel.app/#templates`

3. 若小红书个人页显示 IP 属地异常、网页 SSL 报错、接口连接不稳定，暂停公开发布，只做内部准备。
4. 不为了改变 IP 属地、绕过平台规则或规避风控而调整网络；只使用稳定、合规、可正常访问的网络环境。
5. 发布记录必须备注发布端、网络检查结果和链接检查结果。

### 触发暂停

出现以下任一情况时，Codex 不能继续发布：

- 小红书显示 IP 属地与 Jack 实际使用环境明显不符。
- 工具站链接在直连下无法打开。
- 平台弹出验证码、实名、安全验证、账号异常、限流或违规提示。
- 当前网络频繁中断或发布页上传失败。

## 项目底线

- 不承诺收益
- 不制造焦虑
- 不教灰产
- 不虚构数据、案例、订单
- 不公开隐私和收款码
- 不用 AI 冒充真人体验
- 先验证需求，再做付费产品

## 赚钱路径

当前主线：

AI副业实验室：真实验证普通人可执行的 AI 副业项目，沉淀工具、模板、复盘和低价服务。

优先变现顺序：

1. 免费内容获取反馈
2. 免费模板获取具体需求
3. 低价服务包试单
4. 标准模板包或工具
5. 月度服务或订阅

## 每周复盘问题

- 本周发布了几条内容？
- 有没有具体评论或私信？
- 有没有人愿意提供真实场景？
- 哪个标题/封面/话题表现最好？
- 是否出现付费信号？
- 下周继续、缩小方向，还是换实验？

## Jack 的最小参与

每天只需要做三类动作：

1. 确认是否发布
2. 提供平台验证码或账号权限
3. 回复真实客户或用户消息

除此之外，默认由 Codex 先做出版本，再交给 Jack 判断。

## 手机指挥模式

当 Jack 连续 1-2 天没有时间打开电脑时，项目进入手机指挥模式。

### 可用方式

1. Codex 每天仍在当前线程生成工作包。
2. 如果配置了飞书群机器人，Codex 可以把摘要推送到 Jack 手机飞书。
3. 如果手机 GPT/Codex 无法连接当前线程，Jack 可以使用 GitHub Issue 手机指挥台评论短指令。

### 当前限制

飞书自定义机器人默认适合“发送通知”，不等于 Codex 能自动读取 Jack 在飞书里的回复。  
在没有额外接入消息读取能力前，Jack 在飞书里看到提醒后，可以去 GitHub Issue 手机指挥台回复指令。

手机指挥台：

https://github.com/shamozhizhou325-creator/ai-side-lab/issues/1

### 手机快捷指令

Jack 在手机上可以只发很短的命令：

- `同意发布`：允许发布当前准备好的内容。
- `暂停`：当天停止公开动作，只做内部准备。
- `改标题`：只优化标题，不动正文和封面。
- `改封面`：只优化封面，不动正文。
- `重写`：重新做整篇内容。
- `复盘`：根据已有数据给出下一步判断。
- `今天没空`：Codex 只做可自动完成事项，不再追问。

### 飞书推送格式

如果 `FEISHU_WEBHOOK_URL` 已配置，Codex 每次只推送压缩版：

`【AI副业实验室】今日建议：... 需要你确认：... 手机指挥台：https://github.com/shamozhizhou325-creator/ai-side-lab/issues/1 回复：同意发布/暂停/改标题/重写。`

### 最终发布包发送

当内容进入“最终版待发布”状态时，Codex 可以通过飞书发送小红书手机发布包：

为了方便手机复制，必须分条发送：

1. 封面图 GitHub 下载链接
2. 标题
3. 正文
4. 话题
5. 发布后记录项
6. 安全提醒

发送脚本：

`node scripts/send-xhs-final-packet.mjs`

安全规则：

- 只发送可公开发布的内容。
- 不发送 webhook、验证码、手机号、收款码、身份证、支付信息。
- 封面图使用 GitHub raw 链接，手机端打开后保存到相册再上传小红书。
- 标题、正文、话题必须分别发送，避免手机复制整段消息时选不中。
